63. Root-cause investigation of the missing `encounterId` found the actual break: `PhaseManager.applyServerState()` was still treating encounter lifecycle as a phase-transition concern, but the runtime now stays in `encounter` continuously. That meant initial or later authoritative `encounter_id` values could arrive without ever firing `encounterStart`, so `GameCoordinator` never mirrored the encounter ID into shell state. The fix moves encounter lifecycle emission to `encounter_id` transitions themselves and updates `GameCoordinator` to set `encounterId`, `serverCombatMode`, and `combatActive` from `encounterStart`, restoring the authoritative encounter context path without relying on any legacy phase toggle.
